## Conclusão técnica

**Comprovado no ambiente e cenários testados:** dois GitHub-hosted runners independentes escrevem contra uma referência remota comum. Dois commits irmãos não podem ambos prevalecer com atualização Git não-forçada: um obtém HTTP 200 e o outro 422, confirmado por readback do estado.

**Limitação crítica comprovada:** `PATCH /git/refs` com `force:false` valida a possibilidade de *fast-forward*, **não compara a geração lógica dos dados do ledger**. Um candidato descendente calculado com snapshot obsoleto pode receber HTTP 200 e substituir reservas corretas. Portanto **não chamar esse mecanismo, sozinho, de CAS transacional para orçamento**.

**Não comprovado:** transação distribuída entre referências Git; teto global sob múltiplos escritores que possam criar commits descendentes a partir de snapshots obsoletos; tolerância a falha real de transporte; custo de API paga; proteção forte para produção.

## Recomendações para SDD-0001 v1.2 e ADR-0014 rev.1

1. Preferir **single-writer confiável e serializado por ledger global**, com vários produtores de propostas não privilegiados; validar que a serialização realmente compreende todos os jobs/PRs, não apenas um PR.
2. O escritor precisa validar invariantes e identidade de operação imediatamente antes de persistir, sem usar estado lógico calculado fora da seção crítica.
3. Mesmo com exclusão operacional, implementar **reconciliação após timeout ou erro ambíguo**, readback remoto, chaves idempotentes, teto financeiro conservador e política fail-closed.
4. Se for obrigatório ter escritores ativos simultâneos, escolher armazenamento que ofereça **CAS de valor/versão server-side realmente suportado**, comprovado em concorrência e testes de crash, em vez de assumir isso do Git-ref `force:false`.
5. Separar ledger de push triggers do orquestrador, evitar loop operacional e preservar revisão/auditoria de cada alteração.
6. Não liberar chamadas pagas, gate de merge do SaaS principal ou PHASE-0-G com base apenas neste canary. Abrir revisão arquitetural consolidada com estes resultados antes do próximo Codex Review.
